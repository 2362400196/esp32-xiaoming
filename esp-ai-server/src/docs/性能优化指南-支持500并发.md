# ESP-AI-Server 性能优化指南 - 支持 500+ 设备并发

## 优化概述

本文档描述了 ESP-AI-Server 为支持 **500+ 设备并发** 所做的系统性优化。

## 一、架构优化

### 1.1 高性能连接池 ([connection_pool.py](file:///c:/Users/23624/Desktop/hahahahaahaahha/esp-ai-server/src/infrastructure/connection_pool.py))

**优化策略**：
- **分离锁设计**：只对计数器操作加锁，队列操作无锁
- **快速路径**：优先从队列获取，减少锁持有时间
- **智能预热**：启动时后台异步创建连接
- **详细统计**：记录 acquire/release/create/close 等操作

**配置参数**：
| 参数 | 默认值 | 说明 |
|------|--------|------|
| `max_size` | 100 | 最大连接数 |
| `min_size` | 20 | 最小保持连接数 |
| `idle_timeout` | 300s | 空闲连接超时 |
| `connection_timeout` | 15s | 创建连接超时 |

### 1.2 优化后的队列系统

**[session_fsm.py](file:///c:/Users/23624/Desktop/hahahahaahaahha/esp-ai-server/src/use_cases/session_fsm.py)**：
- 发送队列大小：200 → **500**
- 单写队列化，避免并发写入冲突

### 1.3 优化的设备注册表

**[auxiliary_services.py](file:///c:/Users/23624/Desktop/hahahahaahaahha/esp-ai-server/src/use_cases/auxiliary_services.py)**：
- 添加设备统计（register/unregister/lookup 次数）
- 添加 MAC 双索引加速查询
- 优化 resolve 方法，减少冗余查询

### 6.2 监控脚本示例

```python
import requests

def check_system_health():
    response = requests.get(
        "http://localhost:8088/api/v1/system/metrics",
        headers={"X-API-Key": "your_key"}
    )
    data = response.json()["data"]
    
    devices = data["devices"]["total_devices"]
    memory_percent = data["system"]["memory_percent"]
    
    if devices > 450:
        print(f"⚠️ 设备数接近上限: {devices}/500")
    if memory_percent > 80:
        print(f"⚠️ 内存使用过高: {memory_percent}%")
```

# 音乐播放工具接入指南

本文档介绍如何在 ESP-AI 项目中添加"语音点歌"功能：用户说出歌名 → 服务端搜索歌曲 API → 设备流式播放 HTTP MP3。

---

## 1. 整体架构

```
用户说"播放好运来"
  → ESP32 设备采集音频 → WebSocket 发给服务端
  → 服务端 ASR 识别 → LLM 调用 play_music(song="好运来") 工具
  → play_music 内部:
      1. GET http://192.168.31.176:2233/stream_pcm?song=好运来
      2. 解析返回 {success, title, artist, audio_url, lyric_url, duration}
      3. 发送 instruct(play_music, audio_url) 给设备
      4. raise StopPipeline() 阻止后续 TTS 总结
  → 设备收到 URL → HTTP 流式下载 → mp3_player_write() → I2S 播放
```

## 2. 服务端改动

### 2.1 新增 StopPipeline 异常类

**文件：** `app/tools/__init__.py`

```python
class StopPipeline(Exception):
    """工具抛出此异常以阻止 LLM pipeline 继续生成 TTS 音频。
    用于 play_music、standby 等需要独占音频通道的工具。"""
    pass
```

`StopPipeline` 继承自 `Exception`。当工具抛出它时，整个 LLM → TTS pipeline 会被终止，不再生成语音总结。例如"好的，马上为你播放音乐！"这句话不会合成 TTS，避免和正在播放的音乐抢音频通道。

### 2.2 tool_manager 透传异常

### 2.5 Handler 捕获并清理

**文件：** `app/websocket/handler.py` `send_tts_response` 函数

```python
pipeline_stopped = False
try:
    await llm_task
except StopPipeline:
    pipeline_stopped = True
    # 激进清理：防止 TTS 音频帧与音乐冲突
    await worker_pool.stop()
    if not sender_task.done():
        sender_task.cancel()
    # 排空 audio_queue 和 sentence_queue
    # ...
    channel.clear_queue()
    tts_end_event.set()
    on_done_handler = None   # ← 不触发 ASR 重启，让设备专心播音乐

if pipeline_stopped:
    info("[TTS] 跳过 TTS 收尾（工具已接管音频通道）")
    # 不发送 end_frame、不等待 playback_done，直接跳过
else:

    # ...
```

关键点：`on_done_handler = None` 后不会触发 `_on_tts_complete` → `_start_asr_session`，设备播音乐期间不会误启 ASR。

### 2.6 音乐工具实现

**文件：** `app/tools/builtin.py`

```python
import json
import urllib.request
import urllib.parse
from app.tools import tool, StopPipeline

BASE_URL = "http://192.168.31.176:2233"


@tool()
async def play_music(song: str, tool_manager=None) -> str:
    """搜索并播放歌曲。根据用户说的歌名搜索歌曲，找到后通过设备播放。
参数 song 为用户说的歌名，例如"好运来"、"晴天"、"起风了"等。"""
    # 1. 调用歌曲搜索 API
    try:
        encoded = urllib.parse.quote(song)
        api_url = f"{BASE_URL}/stream_pcm?song={encoded}"
        req = urllib.request.Request(api_url)
        with urllib.request.urlopen(req, timeout=10) as resp:
            data = json.loads(resp.read().decode("utf-8"))
    except Exception as e:
        return f"搜索歌曲失败: {e}"

    if not data.get("success"):
        return f"未找到歌曲: {song}"

    audio_url = data.get("audio_url", "")
    if not audio_url:
        return f"歌曲 {song} 没有可播放的音频链接"

    title = data.get("title", song)
    artist = data.get("artist", "未知")
    lyric_url = data.get("lyric_url", "")
    duration = data.get("duration", 0)

    # 2. 通过 WebSocket 发送播放指令给设备
    if tool_manager and tool_manager.channel:
        tool_manager.channel.send_json_nowait({
            "type": "instruct",
            "command_id": "play_music",
            "data": audio_url,             # ← 纯 URL，客户端直接播放
            "meta": json.dumps({           # ← 歌曲元信息，客户端后续可扩展
                "title": title,
                "artist": artist,
                "lyric_url": lyric_url,
                "duration": duration,
            }, ensure_ascii=False),
        })
        raise StopPipeline()    # ← 停止 LLM/TTS pipeline

    return f"播放音乐指令已生成（未连接设备）"
```

**工具描述要点：**

- 参数 `song: str`，LLM 传入用户所说的歌名
- `tool_manager` 由框架自动注入，可访问 WebSocket 通道
- 用 `send_json_nowait` 而非 `send_json`：绕过音频帧队列，立即发送指令
- `data` 字段发纯 URL，兼容旧客户端
- `meta` 字段携带歌词、歌手等扩展信息

### 2.7 其他需要 StopPipeline 的工具

同样的模式适用于 `standby`（进入待机）工具：

```python
@tool()
async def standby(tool_manager=None) -> str:
    """将设备设置为待机状态，不响应语音指令"""
    if tool_manager and tool_manager.channel:
        await tool_manager.channel.send_json({"type": "session_status", "status": "session_end"})
        await tool_manager.channel.send_text("session_end")
        raise StopPipeline()
    return "已进入待机状态"
```

> **注意：** 抛出 `StopPipeline` 的工具不要用 `try/except Exception` 包裹，否则 `StopPipeline` 会被误吞。

## 3. 客户端改动

### 3.1 修复 malloc + C++ String 导致的堆破坏（必须）

**文件：** `main.cpp`

```cpp
// ❌ 旧代码：malloc 不调用 String 构造函数，params->url 内部指针是随机值
typedef struct {
  String url;               // C++ 对象，有构造/析构函数
} AudioTaskParams;

AudioTaskParams *params = (AudioTaskParams *)malloc(sizeof(AudioTaskParams));
params->url = url;          // ← 在未构造的 String 上调 operator=，堆破坏！
```

```cpp
// ✅ 修复：用 C 字符串
typedef struct {
  char *url;
} AudioTaskParams;

// playNetworkAudio 中：
char *url_copy = (char *)malloc(url.length() + 1);
strcpy(url_copy, url.c_str());
params->url = url_copy;     // ← 使用已分配好的 C 字符串

// audio_play_task 退出时释放：
if (url) free(url);
if (pvParameters) free(pvParameters);
```

**为什么要改：** `malloc` 只分配内存不调用构造函数。`String` 对象内部的缓冲区指针未初始化，赋值操作会先尝试 `free` 随机地址 → 堆破坏 → `Guru Meditation Error: StoreProhibited`。

### 3.3 playNetworkAudio + audio_play_task（已有，无需改动）

```cpp
bool playNetworkAudio(const String &url) {
    // 如果已有任务在运行，等待结束
    if (audio_task_handle != NULL) {
        network_audio_playing = false;
        vTaskDelay(pdMS_TO_TICKS(100));
    }

    char *url_copy = (char *)malloc(url.length() + 1);
    strcpy(url_copy, url.c_str());

    AudioTaskParams *params = (AudioTaskParams *)malloc(sizeof(AudioTaskParams));
    params->url = url_copy;

    network_audio_playing = true;
    xTaskCreate(audio_play_task, "audio_play_task", 8192, params, 5, &audio_task_handle);
    return true;
}

void audio_play_task(void *pvParameters) {
    AudioTaskParams *params = (AudioTaskParams *)pvParameters;
    char *url = params->url;

    HTTPClient http_stream;
    http_stream.begin(url);
    http_stream.setTimeout(10000);
    int streamCode = http_stream.GET();

    if (streamCode > 0) {
        WiFiClient *stream = http_stream.getStreamPtr();
        uint8_t buffer[4096];
        while (network_audio_playing && (http_stream.connected() || stream->available())) {
            if (stream->available()) {
                size_t bytesRead = stream->readBytes(buffer, 4096);
                mp3_player_write(buffer, bytesRead);
            } else {
                vTaskDelay(pdMS_TO_TICKS(10));
            }
        }
        mp3_player_stop();
    }

    http_stream.end();
    free(url);
    free(pvParameters);
    network_audio_playing = false;
    audio_task_handle = NULL;
    vTaskDelete(NULL);
}
```

> **注意：** `audio_play_task` 和 TTS 的 `mp3_player_write` 共享同一个解码器。服务端通过 `StopPipeline` 机制在发送播放指令后立即停止 TTS pipeline，但之前入队的 TTS 音频帧可能仍在传输。建议在 `playNetworkAudio` 开头加 `mp3_player_stop()` 确保解码器清空：
>
> ```cpp
> bool playNetworkAudio(const String &url) {
>     mp3_player_stop();              // ← 增加这行
>     network_audio_playing = false;
>     vTaskDelay(pdMS_TO_TICKS(200)); // ← 等解码器完全停止
>     // ...
> }
> ```

## 4. StopPipeline 异常传播链路

```
play_music() raise StopPipeline
  ↓
tool_manager.call_tool()  except StopPipeline: raise
  ↓
_openai_llm._execute_tool_calls()  穿透
  ↓
openai_llm.stream_chat()  except StopPipeline: info + raise
  ↓
pipeline.llm_pipeline()  except StopPipeline: raise
    finally: sentence_queue.put((-1, None))
  ↓
handler.send_tts_response()  except StopPipeline:
    - 取消 worker_pool、sender_task
    - 排空 audio_queue、sentence_queue、send_queue
    - tts_end_event.set()
    - on_done_handler = None   ← 不重启 ASR
    - 跳过 end_frame / tts_real_end / playback_done
```

## 5. 常见问题

### Q: 播放音乐时设备重启（Guru Meditation Error）

**A:** 检查第 3.1 节的修复是否应用。`malloc` + `String` 是经典坑。另外确保 `network_audio_playing = true` 在 `xTaskCreate` 之后设置，避免任务启动前标志被意外置 false。

### Q: 音乐播放时 TTS 也同时出声

**A:** 检查 `StopPipeline` 异常链是否完整。每一层都必须透传，不能只打日志不 `raise`。特别注意 Python 的 `except Exception` 会捕获 `StopPipeline`（因为它是 `Exception` 的子类），必须放在其前面。

### Q: 播放完音乐后设备无响应

**A:** 服务端 `on_done_handler = None` 后不会自动重启 ASR。音乐播完后设备需要被唤醒（按键或语音唤醒词），生命周期正常。

### Q: 播放自建的 HTTP 音乐服务器

**A:** 修改 `BASE_URL` 指向你的服务器。API 返回格式需为：

```json
{
  "success": true,
  "title": "好运来",
  "artist": "未知艺术家",
  "audio_url": "http://xxx/music/xxx.mp3",
  "lyric_url": "http://xxx/lyrics/xxx.lrc",
  "duration": 200
}
```

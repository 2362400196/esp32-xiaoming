# 设备通信协议文档

## 1. 概述

ESP-AI Server 与设备端（ESP32）之间通过 **WebSocket** 长连接进行实时双向通信。协议包含 JSON 文本消息和二进制音频帧两种格式，覆盖从设备唤醒、语音识别、大模型对话、语音合成到播放完成的全生命周期。

### 1.1 连接参数

设备连接 WebSocket 时通过查询参数传递设备信息：

| 参数名 | 说明 | 示例值 |
|--------|------|--------|
| `v` | 客户端版本 | `2.95.51` |
| `device_id` | 设备唯一标识（MAC 地址） | `D8:3B:DA:6D:D9:3C` |
| `key` | API 密钥（可选） | |
| `ext1` | 扩展参数1 | `0f7ef924...` |
| `ext4` | 协议类型 | `http` |
| `ext5` | 服务器 IP | `192.168.31.176` |
| `ext6` | 服务器端口 | `8088` |
| `ext7` | ASR 类型 | `asrpro` |
| `bitrate` | 音频比特率 | `128` |
| `AUDIO_BUFFER_SIZE` | 音频缓冲区大小 | `10240` |

## 2. 消息分类

### 2.1 消息方向速查

| 方向 | 消息数量 | 说明 |
|------|---------|------|
| D→S | 12 种 | 设备上报状态 + 音频数据 |
| S→D | 15+ 种 | 会话控制 + TTS 音频 + 指令 |

---

## 3. 设备 → 服务器 (D→S)

### 3.1 心跳与会话控制

#### `ping` — 心跳检测

```json
{"type": "ping"}
```

服务器回复 `{"type": "pong"}`。

#### `start` — 开始新会话

触发唤醒后发送，启动语音识别。

```json
{"type": "start"}
```

**服务器响应**：`session_start` → `iat_start`

**打断行为**：若 TTS 正在播放，服务端会立即取消播放、清空队列、发送 `end_frame` + `tts_real_end`，再启动新的 ASR 会话。

#### `iat_end` — 语音结束

设备 VAD 检测到用户说完话，触发 ASR 识别结果回传与 TTS 合成流程。

```json
{"type": "iat_end"}
```

#### `session_stop` — 停止当前会话

设备要求立即终止当前会话（如按键打断）。

```json
{"type": "session_stop", "session_id": "0001"}
```

**服务器响应**：`session_stop_ack`

#### `instruct_ack` — 指令确认

设备收到 `instruct` 消息后的确认应答。

```json
{"type": "instruct_ack"}
```

---

### 3.2 音频播放状态

#### `play_audio_ws_conntceed` — 准备就绪

设备连接成功且准备好接收音频。

```json
{"type": "play_audio_ws_conntceed"}
```

**服务器响应**：发送连接确认 TTS（问候语）。

#### `client_out_audio_over` — 音频播放完成

设备缓冲区排空，音频已完整播放。

```json
{"type": "client_out_audio_over", "session_id": "0001", "session_status": "03", "tts_task_id": ""}
```

**服务器响应**：启动下一轮 ASR（`iat_start`）。

#### `client_available_audio` — 缓冲区余量上报

设备定期上报可用音频缓冲区字节数，服务端据此做流量控制。

```json
{"type": "client_available_audio", "value": 10240}
```

| value 范围 | 服务端行为 |
|-----------|-----------|
| > 8192 (80%) | 暂停发送，等待设备消费 |
| > 5120 (50%) | 降速发送，间隔 100ms |
| ≤ 5120 | 正常发送，间隔 20ms |

此消息也充当 TTS drain 阶段的 TCP ACK 确认。

#### `volume` — 音量上报

设备物理按键改变音量后上报，服务端记录但无响应。

```json
{"type": "volume", "data": 0.7}
```

---

### 3.3 其他

#### `cts_time` — 时间回显

设备对 `stc_time` 的回显，用于测量网络 RTT。

```json
{"type": "cts_time", "stc_time": "1234567890"}
```

---

### 3.4 音频数据（二进制）

设备通过 WebSocket 二进制帧发送 PCM 音频流，单个块大小约 512 字节。服务端将其转发至 ASR 服务做实时识别。

---

## 4. 服务器 → 设备 (S→D)

### 4.1 会话状态 (`session_status`)

全程通过 `session_status` 驱动设备状态机：

| status 值 | 触发时机 | 设备行为 |
|-----------|---------|---------|
| `iat_start` | 会话开始 / 上一轮播放结束 | 打开麦克风，开始录音 |
| `iat_end` | ASR 识别完成 | 关闭麦克风 |
| `tts_chunk_start` | 开始发送 TTS 音频帧 | 准备播放 |
| `tts_chunk_end` | TTS 片段发送完（仅连接问候语使用） | 仅用于连接流程 |
| `tts_real_end` | 所有 TTS 帧已发送 | 排空缓冲区、播放完发送 `client_out_audio_over` |
| `session_end` | 会话终止（超时/待机） | 进入待机/休息状态 |

统一格式：

```json
{"type": "session_status", "status": "<status值>"}
```

---

### 4.2 会话控制

#### `session_start` — 会话开始确认

```json
{"type": "session_start", "session_id": "0001"}
```

#### `session_stop_ack` — 停止确认

```json
{"type": "session_stop_ack", "session_id": "0001"}
```

#### `play_audio` — 即将播放音频

```json
{"type": "play_audio", "tts_task_id": "0010"}
```

#### `stc_time` — 服务端时间戳

```json
{"type": "stc_time", "stc_time": "1234567890"}
```

---

### 4.3 心跳保活

#### `keepalive` — 系统保活

服务端定期发送，防止设备空闲断开。

```json
{"type": "keepalive", "ts": 1714600000}
```

| 场景 | 发送间隔 |
|------|---------|
| TTS 播放期间 | 1 秒 |
| 空闲/待机 | 3 秒 |
| WS Sender 高负载 | 每 50 帧额外插入 |

#### `pong` — 心跳响应

```json
{"type": "pong"}
```

---

### 4.4 `instruct` 指令

通用指令格式，通过 `command_id` 区分指令类型：

```json
{"type": "instruct", "command_id": "<指令名>", "data": "<数据>"}
```

#### `on_iat_cb` — ASR 识别文本

```json
{"type": "instruct", "command_id": "on_iat_cb", "data": "今天天气怎么样"}
```

设备通常将其显示在屏幕上。

#### `on_llm_cb` — LLM 回复文本

```json
{"type": "instruct", "command_id": "on_llm_cb", "data": "今天晴天，25度"}
```

按句子级别发送，延迟 8 帧音频后到达到与语音播报同步。

#### 音量控制指令

| command_id | data | 说明 |
|-----------|------|------|
| `set_volume` | `"0.5"` | 设置绝对音量（0.0-1.0） |
| `add_volume` | `"0.1"` | 增加音量（relative） |
| `subtract_volume` | `"0.1"` | 减小音量（relative） |

---

### 4.5 纯文本消息

#### `session_end` — 会话终止纯文本

在 `session_status: session_end` 之后发送的纯文本字符串（非 JSON），指示设备完全终止会话并停止发送音频。

```
session_end
```

## 5. 二进制音频帧格式

### 5.1 TTS 数据帧

```
┌────────────┬──────────┬─────────────┐
│ session_id │  status  │  audio_data │
│  4 bytes   │  2 bytes │  variable   │
│  (utf-8)   │  (utf-8) │  (raw)      │
└────────────┴──────────┴─────────────┘
```

示例：`b'0010' + b'00' + <音频数据>`（与 esp-ai audio_sender.js 一致，无 data_length 字段）

### 5.2 TTS 结束帧

```
┌────────────┬──────────┐
│ session_id │  "03"    │
│  4 bytes   │  2 bytes │
└────────────┴──────────┘
```

示例：`b'0010' + b'03'`

### 5.3 Session ID 常量

| 常量 | 值 | 用途 |
|------|-----|------|
| `SID_CONNECTED` | `0001` | 连接问候语音频 |
| `SID_TTS` | `0010` | 主 TTS 对话音频 |

### 5.4 状态码

| 状态 | 含义 |
|------|------|
| `00` | 正常音频块（流中间） |
| `03` | 流结束帧，无需继续 |

## 6. 完整会话生命周期

### 6.1 正常对话流程

```
┌──────────┐                    ┌──────────┐
│  设备端   │                    │  服务器   │
└────┬─────┘                    └────┬─────┘
     │                               │
     │  ① WebSocket 连接              │
     │  (带查询参数)                   │
     │ ─────────────────────────────> │
     │                               │ ② 发送 play_audio_ws_conntceed
     │ <───────────────────────────── │
     │                               │
     │ ③ play_audio_ws_conntceed     │
     │ ─────────────────────────────> │ ④ 发送连接问候语音频
     │ <─ stc_time                   │
     │ <─ tts_chunk_start            │
     │ <─ [二进制: SID_CONNECTED]     │
     │ <─ [二进制: end_frame]         │
     │ <─ tts_chunk_end              │
     │ <─ session_end (JSON+纯文本)    │
     │                               │
     │ ⑤ 用户唤醒 → start             │
     │ ─────────────────────────────> │ ⑥ 启动 ASR
     │ <─ session_start              │
     │ <─ iat_start                  │
     │                               │
     │ ⑦ 发送音频流 (PCM)             │
     │ ====[二进制×N]==============> │ → ASR 实时识别
     │    client_available_audio     │   流量控制
     │                               │
     │ ⑧ iat_end (或超时)             │
     │ ─────────────────────────────> │ ⑨ LLM → TTS
     │ <─ iat_end                    │
     │ <─ on_iat_cb (识别文本)        │
     │ <─ play_audio                 │
     │ <─ tts_chunk_start            │
     │ <─ [二进制: SID_TTS × N]       │ ← Pipeline 流式发送
     │ <─ on_llm_cb (LLM 文本)        │   延迟8帧同步
     │ <─ [二进制: end_frame SID_TTS] │
     │ <─ tts_real_end               │
     │                               │
     │ ⑩ 播放完成                     │
     │ ─ client_out_audio_over ────> │ ⑪ 启动下一轮 ASR
     │ <─ iat_start                  │
     │                               │
     │ ⑫ 用户不说话 → 超时             │
     │ <─ session_end                │ → 进入待机
```

### 6.2 打断流程

```
TTS 播放中...
     │ ⑬ 用户按键/唤醒 → session_stop 或 start
     │ ─────────────────────────────> │ ⑭ 取消 TTS 任务
     │                               │    清空发送队列
     │ <─ [二进制: end_frame SID_TTS] │    发送 end_frame
     │ <─ tts_real_end               │    通知设备停止播放
     │                               │
     │ <─ session_stop_ack           │ ⑮ 启动新 ASR 会话
     │ <─ session_start              │
     │ <─ iat_start                  │
```

### 6.3 工具调用流程

```
TTS 播放中（LLM→TTS 循环）...
     │                               │ ⑯ LLM 返回 tool_calls
     │                               │    执行工具 (如 set_volume)
     │ <─ set_volume instruct        │ ← ToolManager 通过 channel 发送
     │                               │    LLM 根据工具结果生成总结
     │ <─ [二进制: SID_TTS 继续播放]   │ ← 最终回复走 TTS
```

## 7. 会话状态机

服务端内部通过有限状态机管理每个连接的会话：

```
IDLE ──(start)──> ASR ──(text_ready)──> LLM ──(prompt_ready)──> TTS
  ^                 │                                                   │
  │                 │                                                   │
  └──(no_speech)────┘                     ┌──(done)────────────────────┘
                                          │
  ┌──(session_stop)───────────────────────┘
```

合法转换：
- `IDLE` → `ASR`
- `ASR` → `LLM`、`IDLE`
- `LLM` → `TTS`
- `TTS` → `ASR`、`IDLE`

## 8. 关键超时与阈值

| 配置项 | 默认值 | 说明 |
|--------|-------|------|
| `ASR_NO_SPEECH_TIMEOUT` | 5s | ASR 启动后无识别结果（基于启动时间，不受设备音频包刷新影响） |
| `ASR_SILENCE_TIMEOUT` | 2s | 最后一次识别结果后静默多久触发 VAD 结束 |
| TTS drain ACK 等待 | 15s | 等待设备 TCP ACK 的最长时间 |
| TTS 播放完成等待 | 60s | 等待 client_out_audio_over 的最长时间 |
| WebSocket ping 间隔 | 20s | uvicorn 协议级 ping，防止 Windows IOCP 超时 |
| keepalive 频率 (TTS) | 1s | TTS 播放期间保活密度 |
| keepalive 频率 (空闲) | 3s | 空闲期间保活密度 |
| 音频缓冲区上限 | 10240B | 超过 80% 暂停发送，50% 降速 |
| LLM 工具调用最大轮数 | 5 | 防止死循环 |

## 9. 错误处理

| 异常类型 | 处理方式 |
|---------|---------|
| `WebSocketDisconnect` | 清理会话资源，设置 `connected = False` |
| JSON 解析失败 | 跳过该消息，继续处理下一条 |
| TTS 任务超时 | 强制结束，发送 `tts_real_end` |
| TTS 合成失败 | Worker 跳过当前句子，继续合成下一句 |
| ASR 连接失败 | 自动重试 3 次 |
| OSError（如 WinError 121 信号灯超时） | 由 uvicorn `ws_ping_interval` 预防 |

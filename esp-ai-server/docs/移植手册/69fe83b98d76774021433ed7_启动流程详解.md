# ESP-AI Server 启动流程详解

## 📋 概述

ESP-AI Server 是一个基于 FastAPI + asyncio 构建的智能语音后端服务，专为 ESP32 等硬件设备提供完整的语音交互解决方案。

**当前版本**: v2.82.70

## 🚀 完整启动流程

### 阶段6：Lifespan启动钩子 (app/main.py 第68-83行)

**这是最核心的启动逻辑！** 当 uvicorn 启动时，会自动执行 `_lifespan` 函数的 `yield` 之前部分：

```python
@asynccontextmanager
async def _lifespan(_app: FastAPI):
    # ========== 启动时执行 ==========
    
    # 1️⃣ 启用traceId中间件日志
    info("[Trace] traceId 中间件已启用")
    
    # 2️⃣ 暴露Prometheus监控端点
    info("[Metrics] Prometheus /metrics 端点已暴露")
    
    # 3️⃣ 初始化表情资源目录
    static_dir = os.path.join(os.path.dirname(__file__), "emotion", "static_emos")
    os.makedirs(static_dir, exist_ok=True)
    _app.mount("/emos", StaticFiles(directory=static_dir), name="emos")
    info(f"[Static] 表情资源目录已注册: /emos -> {static_dir}")
    
    # 4️⃣ 初始化工具管理器（自动发现内置工具 + MCP工具）
    await init_tool_manager()  # <-- 关键！发现所有工具
    
    yield  # <-- 服务运行中...
    
    # ========== 关闭时执行 ==========
    # 优雅退出逻辑...
```

### 阶段8：中间件注册 (app/main.py 第118-130行)

```python
@app.middleware("http")
async def trace_id_middleware(request: Request, call_next):
    # 为每个HTTP请求生成trace_id
    trace_id = request.headers.get("X-Trace-Id") or str(uuid.uuid4())
    request.state.trace_id = trace_id
    token = trace_id_var.set(trace_id)
    
    start = time.time()
    try:
        response = await call_next(request)
        response.headers["X-Trace-Id"] = trace_id
        response.headers["X-Response-Time"] = f"{(time.time() - start) * 1000:.1f}ms"
        return response
    finally:
        trace_id_var.reset(token)
```

**功能：**
- 为每个HTTP请求生成唯一的 `trace_id`
- 记录请求处理时间
- 全链路追踪（trace_id 从 HTTP → WebSocket → Session）

## 🔍 关键组件说明

### 1. SessionController

会话控制器，负责管理所有活跃的客户端会话。

```python
# app/websocket/handler.py
_shared_session_controller = SessionController()
voice_generator = _shared_session_controller.voice_generator
info("SessionController 已初始化")
```

**功能：**
- 创建和销毁会话
- 管理活跃会话列表
- 提供共享的 VoiceGenerator 实例

### 2. ToolManager

工具管理器，负责发现和管理所有可用的工具。

```python
# app/websocket/handler.py
async def init_tool_manager():
    global _shared_tool_manager
    _shared_tool_manager = ToolManager()
    _shared_tool_manager.ensure_discovered()
```

**功能：**
- 自动发现 `app/tools/` 目录下的内置工具
- 自动发现 `app/tools/custom/` 目录下的自定义工具
- 缓存工具 Schema 供 LLM Function Calling 使用
- 支持 MCP (Model Context Protocol) 外部工具

### 3. Lifespan 上下文管理器

FastAPI 的现代生命周期管理方式，替代了旧的 `on_event` 装饰器。

```python
@asynccontextmanager
async def _lifespan(_app: FastAPI):
    # 启动逻辑
    await init_tool_manager()
    yield
    # 关闭逻辑（优雅退出）
```

**优势：**
- 异步支持
- 明确的启动/关闭分离
- 异常安全

### 4. 配置系统

使用 Pydantic Settings 实现强类型配置管理。

```python
# app/config.py
class Settings(BaseSettings):
    model_config = {
        "env_file": ".env",
        "env_file_encoding": "utf-8",
    }
    
    # 服务器配置
    host: str = "0.0.0.0"
    port: int = 8088
    
    # LLM配置
    llm_api_key: str = ""
    llm_base_url: str = ""
    llm_model: str = ""
    
    # TTS配置
    tts_volcengine_api_key: str = ""
    # ... 更多配置
```

**配置优先级：**
1. 环境变量
2. `.env` 文件
3. 代码中的默认值

## 📝 启动问题排查

### 1. 端口被占用

```
Error: [Errno 98] Address already in use
```

**解决方案：**
```bash
# 查找占用端口的进程
lsof -i :8088

# 杀死进程或更换端口
# 修改 .env: PORT=8089
```

### 2. 配置文件未加载

```
[Config] WARN: 以下关键配置为空: LLM_API_KEY
```

**解决方案：**
```bash
# 确保 .env 文件存在
cp .env.example .env

# 编辑 .env 填入正确的 API Key
```

### 3. 工具发现失败

```
[ERROR] [ToolManager] 工具发现异常
```

**解决方案：**
- 检查 `app/tools/__init__.py` 是否存在
- 检查工具文件语法是否正确
- 查看详细错误日志

### 4. WebSocket 连接失败

```
WebSocket connection failed
```

**解决方案：**
- 检查防火墙设置
- 确认设备固件中的 WebSocket URL 正确
- 检查 `AUTH_API_KEY` 配置是否匹配

## 🎯 启动性能优化

### 1. 预热连接池

在 `init_tool_manager()` 中预热 ASR/TTS 连接池：

    from app.tts.volcengine import VolcEngineTTS

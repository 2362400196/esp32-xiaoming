# 03 - 权限与安全

插件体系有三层防护（实现见 `src/infrastructure/plugin_security.py` 与 `src/infrastructure/plugin_host/adjudicator.py`）：

1. **静态审计（AST）**：加载插件前扫描其所有 `.py` 源码，提取实际使用的"危险能力集合"，与 `manifest.permissions` 声明比对——未声明直接拒绝加载。
2. **运行时守卫**：SDK 入口在执行时再次校验权限（contextvars 注入插件上下文），动态 import 绕过静态审计也无法越权。
3. **子进程沙箱**（安装插件）：独立进程 + 模块导入黑名单 + RPC 边界裁决（权限/SSRF/设备作用域/环境变量白名单）。

## 1. manifest.permissions 全部可选值

| 权限 | 含义 | 覆盖的 SDK 调用 |
|------|------|----------------|
| `network` | 出站网络访问 | `http_request`、`http_get_json`、`http_stream_open/read/close`、`ws_connect/send/recv/close`、直接使用 httpx/requests/aiohttp/urllib/socket（仅内置插件） |
| `device` | 设备指令下发与设备查询 | `send_instruct`、`send_device_command`、`send_device_command_ack`、`request_device_result`、`device_is_online`、`device_get_info`，以及**设备 IO**（`gpio_mode`、`gpio_write`、`gpio_read`、`pwm_write`、`adc_read`、`servo_write`）和**音乐播放** `play_music_url` |
| `ltm` | 长期记忆存取 | `get_ltm_service` / `get_default_ltm_service` |
| `file_read` | 读插件数据 | `plugin_data_read`、`plugin_data_list`（以及 `open()` 读 / `Path.read_*`） |
| `file_write` | 写插件数据 | `plugin_data_write`、`plugin_data_delete`（以及 `open()` 写 / `Path.write_*`/`unlink`/`mkdir` 等） |
| `subprocess` | 子进程执行 | `subprocess`、`os.system/popen/spawn/exec`（仅内置插件可用，沙箱直接禁止导入） |
| `exec` | 动态代码执行 | `eval` / `exec` / `compile` / `__import__` |
| `db` | 数据库访问 | `sqlite3`/`sqlalchemy` 等（仅内置插件）；SDK 的 `get_diary_repository`、`get_device_repository`、`get_user_profile_summary` |
| `env_read` | 读取环境变量 | `os.environ` / `os.getenv`；SDK 的 `get_plugin_config_or_env(env_var=...)` 也受环境变量白名单二次限制 |
| `llm` | LLM 对话 | `llm_chat`、`llm_generate` |
| `tts` | TTS 语音合成 | `tts_synthesize` |
| `kv` | 键值存储 | `kv_get`、`kv_set`、`kv_delete`、`kv_list` |

> 说明：`gpio_* / pwm_write / adc_read / servo_write / play_music_url` 属于 SDK 白名单通道，静态审计不会把它们的函数名判为危险能力，但**运行时强制校验 `device` 权限**（沙箱由裁决器校验，进程内由 `require_permission` 校验）。声明 `device` 即可。

## 2. 静态审计规则（加载前）

- 扫描范围：插件目录下**所有 `.py` 文件**（含 plugin.py import 的兄弟模块）。
- 危险调用识别（命中即要求声明对应权限）：
  - 属性前缀：`httpx`、`requests`、`aiohttp`、`urllib.request`、`urlopen`、`socket`、`websockets` → `network`；`subprocess`、`os.system/popen/spawn/exec` → `subprocess`；`sqlite3`、`sqlalchemy`、`psycopg`、`pymysql`、`MySQLdb` → `db`；`os.environ`、`os.getenv` → `env_read`；`eval`/`exec`/`compile`/`__import__` → `exec`。
  - `open()`：按 mode 参数判定，读 → `file_read`，含 `w/a/x/+` → 追加 `file_write`；`Path.read_text/read_bytes/readlines` → `file_read`；`Path.write_text/write_bytes/touch/unlink/rename/rmdir/mkdir` → `file_write`。
- **SDK 白名单通道豁免**：`send_device_command`、`http_request`、`llm_chat`、`kv_get` 等受控 SDK 函数名不会被审计为危险调用（它们由运行时按权限拦截）。插件应始终通过 SDK 访问服务器能力。
- 审计出的能力集合 ⊄ 声明集合 → 拒绝加载，日志会列出未声明的能力。
- 另有**包签名/文件哈希校验**（`verify_package`）：marketplace 发布包被篡改时拒绝加载（手写插件无签名则跳过该项）。

## 3. 运行时权限守卫

- 插件工具执行期间，框架把 `(plugin_id, permissions)` 注入 contextvar；SDK 入口调用 `require_permission(权限名)` 二次校验。
- 未声明 → 抛 `PermissionError`（沙箱下经 RPC 映射为同样的 `PermissionError` 语义传回插件代码）。
- 非插件调用（CLI/内置工具）上下文为空，不拦截。

## 4. 沙箱限制（安装插件）

沙箱插件运行在独立子进程（`plugin_host/`），限制如下：

### 4.1 模块导入黑名单（加载即拒绝）

以下模块**不能 import**（节选，完整清单见 `src/infrastructure/plugin_host/sandbox.py` 的 `_BLOCKED_MODULES`）：

- 进程/系统：`subprocess`、`multiprocessing`、`ctypes`、`signal`、`resource`、`shutil`、`tempfile`
- 网络：`socket`、`ssl`、`http.client`、`http.server`、`urllib.request`、`httpx`、`requests`、`aiohttp`、`urllib3`、`websockets`、`websocket`、`smtplib`、`ftplib`、`telnetlib`
- 动态加载/反射：`importlib`（全部子模块）、`runpy`、`trace`、`marshal`、`pickle`、`shelve`
- 数据库：`sqlite3`、`sqlalchemy`、`pymysql`、`psycopg`、`MySQLdb`、`aiomysql`
- 文件/压缩：`zipfile`、`tarfile`、`gzip`、`bz2`、`lzma`
- 其他：`pdb`、`distutils`、`setuptools`、`pip`、`site`、`platform`、`gc`、`tkinter`、`winreg` 等

放行的常用标准库（`_ALLOWED_MODULES`）：`json`、`re`、`datetime`、`time`、`uuid`、`math`、`random`、`hashlib`、`hmac`、`base64`、`asyncio`、`dataclasses`、`typing`、`os`、`sys`、`pathlib`、`logging`、`threading` 等。

**服务器内部模块**：插件一律不能直接 import；SDK 由桩模块提供——允许（且只允许）导入：

- `src.use_cases.tools_system`（`@tool` / `StopPipeline`，桩实现）
- `src.use_cases._plugin_helpers`（SDK 统一入口，桩实现）
- `src.domain` / `src.domain.entities` / `src.domain.value_objects`（只读数据类）

### 4.2 RPC 边界裁决（每个 SDK 调用）

主进程裁决器（`adjudicator.py`）对每个 SDK 请求执行：

- **权限校验**：op → 权限映射（`_OP_PERMS`），未声明即拒绝；未知 op 直接拒绝。
- **URL 校验（SSRF 防护）**：仅允许 `http/https/ws/wss`；DNS 解析后命中内网/回环/链路本地（含云元数据 `169.254.169.254`）/保留地址一律拦截，并做 IP pinning 防 DNS 重绑定。可用环境变量 `PLUGIN_URL_ALLOWLIST`（逗号分隔域名）配置业务白名单——白名单域名同样走 SSRF 校验，不会豁免。
- **环境变量白名单**：只允许读 `<插件ID>_` 前缀或 `PLUGIN_` 前缀变量；管理员可用 `PLUGIN_ENV_ALLOWLIST` 显式放行个别变量。
- **设备作用域**：日记、设备配置、用户画像、LTM、设备 IO（gpio/pwm/adc/servo）、音乐播放等操作强制限定在本次调用绑定的设备；未绑定设备时禁止指定其他设备，绑定后只能操作绑定设备。
- **资源限制**：单条 RPC 消息最大 1MB；SDK 请求超时 60 秒；单次工具调用超时 130 秒。

### 4.3 其他安全机制

- **工具名冲突检测**：插件工具与系统工具/其他插件工具重名 → 拒绝加载。
- **插件日志**：`plugin_log` 写入插件日志存储（`data/plugins/state/<插件ID>/plugin.log`），stderr 一并捕获，便于事后审计。
- **配置脱敏**：`mask_secret` / `mask_dict_secrets` 对密钥类配置（`*key`/`*token`/`*secret`/`*password`/`*appid` 等）掩码，防止日志泄露。

## 5. 设备作用域详解

框架为每次工具调用绑定一个设备上下文（`ctx.device_key`，`bound_xxx` 格式）：

| 场景 | 行为 |
|------|------|
| API 调用未传 `device_key` | 自动使用绑定设备 |
| 显式传入绑定设备自身 | 允许 |
| 显式传入其他设备 | **拒绝**（PermissionDenied），日志记录 |
| 插件未绑定设备，却指定了目标设备 | **拒绝** |

适用 API：`get_device_info`、LTM 全部操作、日记全部操作、设备配置读写、`get_user_profile_summary`，以及设备 IO（`gpio_mode/gpio_write/gpio_read/pwm_write/adc_read/servo_write`）与 `play_music_url`。

# 01 - 快速开始：从零写一个最小插件

本教程面向**只使用插件 SDK、不需要了解框架内部**的开发者。10 分钟内写一个能被语音助手调用的最小插件。

## 1. 插件有两种放置方式

| 类型 | 位置 | 加载方式 | 说明 |
|------|------|----------|------|
| 内置插件 | `src/plugins/<插件ID>/` | 进程内加载 | 随源码分发，受信任 |
| 安装插件 | `data/plugins/installed/<插件ID>/` | **子进程沙箱** | 第三方插件，权限严格隔离 |

两者目录结构、manifest.json、`@tool` 写法完全一致。第三方开发者开发完成后，把插件目录放进 `data/plugins/installed/` 即可；同名时安装版优先于内置版。

> 沙箱插件不能直接 import 服务器内部模块（如 `httpx`、`sqlite3`），所有服务器能力都要通过 SDK（`src.use_cases._plugin_helpers`）调用，详见 [03-权限与安全](03-权限与安全.md)。

## 2. 目录结构

```
my_hello/                 # 目录名即插件 ID
├── manifest.json         # 必须：插件清单
└── plugin.py             # 必须：插件入口（工具定义写在这里）
```

可选文件：`icon.png`（图标，zip 包内通过 manifest 的 `icon` 字段引用）、同目录其他 `.py` 模块（plugin.py 可以 `import` 兄弟模块）。

## 3. manifest.json 完整字段说明

```json
{
    "id": "my_hello",
    "name": "打招呼",
    "version": "1.0.0",
    "author": "your-name",
    "description": "向用户问好并点亮 LED",
    "api_version": "1.0",
    "requires": [],
    "permissions": ["device"]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | str | 是 | 插件 ID，英文（校验规则：`^[a-z][a-z0-9_]*$` 风格，见 `plugin_manifest.py`），必须与目录名一致 |
| `name` | str | 是 | 显示名称（中文） |
| `version` | str | 否 | 语义化版本，默认 `"1.0.0"` |
| `author` | str | 否 | 作者 |
| `description` | str | 否 | 描述 |
| `icon` | str | 否 | 图标文件名（zip 包内，如 `"icon.png"`） |
| `api_version` | str | 否 | API 兼容版本，当前仅支持 `"1.0"` |
| `requires` | list | 否 | 能力要求，如 `["display"]`（声明插件依赖的其他能力/插件提供的服务） |
| `dependencies` | list | 否 | 依赖的其他插件 ID 列表 |
| `config_fields` | list | 否 | 用户可配置项声明（每项为 dict：名称/类型/默认值等，用于前端生成配置表单） |
| `permissions` | list | 否 | **权限声明**，全部可选值见 [03-权限与安全](03-权限与安全.md)。SDK 能力（网络/设备/存储等）必须在此声明，否则调用被拒 |
| `optional` | bool | 否 | `true` 表示可选插件（默认不安装） |
| `frontend` | bool | 否 | 是否有前端页面 |
| `frontend_config` | dict | 否 | 前端页面配置（如 `nav_label`/`nav_icon`/`width`） |
| `provides` | dict | 否 | 声明本插件提供的服务类型（服务注册表用），如 `{"tts": ["my_tts"]}` |
| `file_hashes` / `signature` | - | 否 | 发布包文件哈希与 Ed25519 签名（marketplace 打包工具自动生成，手写插件不需要） |

## 4. plugin.py：用 @tool 定义工具

工具 = LLM 可以调用的函数。写法：

```python
# my_hello/plugin.py
from src.use_cases.tools_system import tool
from src.use_cases._plugin_helpers import gpio_write, plugin_log


@tool(name="say_hello", description="向用户打招呼，并可选地点亮开发板 LED")
async def say_hello(message: str, led: bool = False) -> str:
    """函数 docstring 会成为工具描述（若未显式传 description）。"""
    plugin_log(f"say_hello 被调用: {message}")
    reply = f"你好！{message}"
    if led:
        # 设备 IO 需要 manifest 声明 "device" 权限
        result = await gpio_write(2, 1)   # GPIO2 拉高
        if result != "ok":
            reply += f"（LED 点亮失败: {result}）"
    return reply
```

`@tool` 规则（与主进程完全一致，见 `src/use_cases/tools_system.py`）：

- `name`：默认取函数名；`description`：默认取 docstring。
- `cache`：默认 `True`，相同参数 300 秒内复用结果。**有副作用（控制硬件、发设备指令、刷屏幕）的工具必须显式 `cache=False`**，否则缓存命中会跳过整个函数。
- 参数类型注解映射：`int`→integer、`float`→number、`bool`→boolean、`list`→array、`dict`→object，**其他/缺省一律 string**。无默认值的参数为必填。
- `tool_manager`、`channel`、`ctx`、`fsm` 参数不会出现在工具 schema 中（框架注入用）；沙箱插件直接调用 SDK 即可，不需要这些参数。
- **工具名不能与系统工具或其他插件工具重名**，冲突时插件拒绝加载。

## 5. 安装到设备

1. 把插件目录放到 `data/plugins/installed/my_hello/`（或打 zip 通过 marketplace 安装）。
2. 重启服务，或通过插件管理接口触发重载（`plugin_loader.reload_single_plugin("my_hello")`）。
3. 启动日志出现 `[插件] my_hello ...` 即加载成功；若被拒绝，日志会给出明确原因（权限未声明 / 工具名冲突 / 安全审计不通过 / 沙箱导入被拒）。

## 6. 调试方法与日志查看

**插件内打日志**：`plugin_log("消息", level="info")`，level 可用 `debug / info / warn / error`。

日志去向：

- 内存环形缓冲 + 文件 `data/plugins/state/<插件ID>/plugin.log`（可通过日志查询接口按插件读取，最新在前）。
- 沙箱插件的子进程 stderr 也会被主进程捕获，以 `stderr` 级别记入同一日志。
- 服务器主日志（控制台/日志文件）会有 `[插件]`、`[插件沙箱]` 前缀的框架日志：加载失败原因、HTTP 拦截、权限拒绝（`SDK xxx 权限被拒`）等都在这里。

**排查清单**：

| 现象 | 原因 |
|------|------|
| 插件没加载 | manifest.json 格式错误 / `id` 与目录名不一致 / `api_version` 不是 `"1.0"` |
| 加载被拒绝，提示权限 | 代码用到的 SDK 能力未在 `permissions` 声明（静态审计） |
| 运行时报 `PermissionError: ... 未声明 xxx 权限` | 同上，但属于运行时拦截（动态 import 也逃不掉） |
| 工具没出现在工具列表 | 工具名与系统工具/其他插件冲突，或 plugin.py 语法错误 |
| SDK 调用无响应后报超时 | 设备不在线/未连接（设备指令类返回 `设备未连接` 或超时状态） |

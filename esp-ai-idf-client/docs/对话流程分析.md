# ESP-AI IDF Client 对话流程详解

## 一、无法对话的根因

### 核心问题：I2S 麦克风句柄竞争

ESP32-S3 的 WakeNet 语音唤醒任务和 ASR 麦克风采集任务**共享同一个 I2S 通道句柄**（`s_wakenet_mic_handle`）。当两个任务同时调用 `i2s_channel_read()` 读取同一个句柄时，音频数据会被随机分配给两个任务，导致：

- ASR 麦克风采集任务收到的数据不完整或全是静音（值为 125 的无效数据）
- 服务端 ASR 引擎收到 124800 bytes 数据但识别为"无有效语音"
- 对话流程在 `iat_start` 阶段就失败，无法进入 LLM 推理

### 具体的错误调用链

```
唤醒成功
  → wakeup_pause()  ✓ WakeNet 暂停
  → 发送 {"type":"start"}
  → 服务端返回 play_audio (唤醒提示音 0010)
  → 服务端返回 play_audio (连接问候音频 0001)
  → 两个 "03" 二进制结束帧先后到达
  → drain_check_timer_cb() 触发
    → send_audio_over()
      → wakeup_resume()  ✗ 错误！WakeNet 恢复，重新读取 I2S
  → 服务端返回 iat_start
    → audio_mic_start()  mic_task 开始读取 I2S
    → WakeNet task 也在读取 I2S  → 竞争！数据损坏
  → ASR 识别失败 → 对话中断
```

### 修复方案

在整个对话会话期间（从唤醒到 session_end），**WakeNet 保持暂停状态**，只有 mic_task 独占 I2S 句柄：

| 函数 | 修复前 | 修复后 |
|------|--------|--------|
| `send_audio_over()` | 调用 `wakeup_resume()` | **不调用** |
| `drain_check_timer_cb()` s_session_ended 分支 | 调用 `wakeup_resume()` | **不调用** |
| `session_end` (JSON/纯文本) | 调用 `wakeup_resume()` | 保持调用（会话真正结束） |

## 二、完整对话流程

### 阶段 0：系统初始化

```
app_main()
  ├── nvs_flash_init()           // NVS 初始化
  ├── register_callback_commands() // 注册指令回调
  ├── board_init()               // 板级包初始化（GPIO、I2S 引脚配置）
  ├── display_init()             // 显示初始化（LVGL 9 + ST7789）
  │   └── 表情: 休息中
  ├── wakeup_init()              // 唤醒模块初始化
  │   ├── AFE 配置（无 AEC/VAD/NS/AGC）
  │   ├── 创建 I2S 麦克风通道 (s_wakenet_mic_handle, 16kHz)
  │   └── 加载 WakeNet 模型 (wn9_xiaomingtongxue_tts2)
  ├── audio_init()               // 音频系统初始化
  │   ├── 复用 WakeNet 的 I2S 麦克风句柄
  │   ├── 初始化 I2S 喇叭 (MAX98357A, 24kHz)
  │   └── 初始化 MP3 解码器 (helix)
  ├── wifi_init()                // WiFi 连接
  ├── websocket_init()           // WebSocket 连接服务端
  └── wakeup_start()             // 启动唤醒检测
      ├── button_wakeup_task (Core 1, 优先级 2)  // 按钮唤醒
      └── wakenet_task (Core 0, 优先级 2)        // 语音唤醒
```

### 阶段 1：待机等待唤醒

```
状态: 等待唤醒...
表情: 休息中
WakeNet: 运行中（持续读取 I2S 麦克风）
mic_task: 未启动

wakenet_task 循环:
  while (s_wakeup_running):
    if (s_wakenet_paused):    // false（正常运行）
      vTaskDelay(50ms)
      continue
    i2s_channel_read(feed_buf)  // 读取 512 samples
    afe->feed(feed_buf)         // 喂给 AFE
    result = afe->fetch()       // 获取 WakeNet 结果
    if (result->wakeup_state == WAKENET_DETECTED):
      → 触发唤醒事件

button_wakeup_task 循环:
  while (s_wakeup_running):
    if (GPIO0 == 0):  // 按钮按下
      → 触发唤醒事件
    vTaskDelay(10ms)
```

### 阶段 2：唤醒触发

```
唤醒触发（语音或按钮）
  ├── wakeup_pause()
  │   └── s_wakenet_paused = true
  │   └── 等待 wakenet_task 停止读取 I2S（s_wakenet_reading = false）
  ├── s_session_state = SESSION_LISTENING
  ├── websocket_send_text({"type":"start"})  // 通知服务端开始会话
  ├── display_show_status("聆听中")
  └── display_show_emotion("聆听中")

此时:
  WakeNet: 已暂停（不读取 I2S）
  mic_task: 未启动
  I2S 麦克风: 空闲
```

### 阶段 3：服务端响应 - 连接确认

```
收到: {"type":"play_audio_ws_conntceed"}
  └── 回复: {"type":"play_audio_ws_conntceed"}

收到: {"type":"session_start","session_id":"0001"}
  └── 记录 s_current_session_id = "0001"

收到: {"type":"play_audio","tts_task_id":"0010"}
  ├── s_current_tts_task_id = "0010"
  ├── s_audio_playing = true
  ├── s_audio_over_sent = false      ← 防止重复发送
  ├── s_session_ended = false        ← 清除上轮残留状态
  ├── s_id3_skip_size = 0
  └── audio_spk_play()               // 启动喇叭播放任务
```

### 阶段 4：接收 TTS 音频数据

```
收到二进制音频帧（WebSocket op_code=0x02）:
  格式: [4字节 session_id][2字节 status][N字节 MP3 数据]

处理流程:
  ├── 解析 session_id (如 "0001")
  ├── 解析 status:
  │   ├── "01" = TTS 片段结束（继续等待更多数据）
  │   ├── "02" = TTS 结束，继续对话 → 设置 s_continue_dialogue = true
  │   └── "03" = TTS 结束，会话结束 → 设置 s_session_ended = true
  ├── 跳过 ID3v2 标签（MP3 元数据）
  └── audio_spk_write(audio_data, audio_len)  // 写入喇叭缓冲区

同时收到时间同步:
  {"type":"stc_time","stc_time":"1234567890"}
  └── 回复: {"type":"cts_time","stc_time":"1234567890"}
```

### 阶段 5：TTS 音频开始播放

```
收到: {"type":"session_status","status":"tts_chunk_start"}
  ├── s_audio_playing = true
  ├── display_show_status("说话中")
  └── display_show_emotion("说话中")

音频播放任务 (audio_task, Core 0):
  while (s_spk_playing):
    mp3_data = ring_buffer_read()
    pcm_data = MP3_Decode(mp3_data)     // helix MP3 解码
    i2s_channel_write(spk_handle, pcm_data)  // I2S 输出到 MAX98357A
```

### 阶段 6：TTS 音频结束（二进制 "03"）

```
收到二进制帧 status="03"（0 payload，表示 TTS 全部结束）
  ├── s_session_ended = true
  ├── s_continue_dialogue = false
  ├── s_audio_playing = false
  ├── callback_reset_llm_text()        // 清空 LLM 文本缓冲
  ├── s_current_tts_task_id = ""
  ├── audio_spk_wait_drain()           // 设置 s_spk_wait_drain = true
  └── 启动 drain_check_timer（200ms 周期）
      └── 每 200ms 检查音频缓冲区是否排空

drain_check_timer_cb():
  if (!audio_spk_check_drain_done()):
    return  // 音频还没播完，继续等
  // 音频播完了
  if (s_session_ended):
    ├── s_session_ended = false
    ├── send_audio_over_internal()     // 发送 client_out_audio_over
    ├── display_show_status("等待唤醒...")
    ├── display_show_emotion("休息中")
    └── 【不恢复 WakeNet】              ← 关键修复！
  elif (s_continue_dialogue):
    └── 见阶段 8（连续对话）
```

### 阶段 7：发送 client_out_audio_over + 进入 ASR

```
send_audio_over_internal():
  if (s_audio_over_sent): return       ← 防止重复发送
  s_audio_over_sent = true
  发送: {"type":"client_out_audio_over",
         "session_id":"0001",
         "session_status":"03",
         "tts_task_id":""}

收到: {"type":"session_status","status":"iat_start"}
  ├── 停止 drain_check_timer           ← 避免与 mic 竞争
  ├── audio_spk_stop()                 // 停止喇叭播放
  ├── callback_reset_llm_text()        // 清空 LLM 文本
  ├── if (!wakeup_is_paused()):        // 确保 WakeNet 暂停
  │     wakeup_pause()
  ├── display_show_status("聆听中")
  ├── display_show_emotion("聆听中")
  └── audio_mic_start()                // 启动麦克风采集任务

此时:
  WakeNet: 已暂停（不读取 I2S）        ← 关键！独占 I2S
  mic_task: 运行中（独占读取 I2S）
  喇叭: 已停止
```

### 阶段 8：麦克风采集 + ASR 识别

```
mic_task (audio.c, Core 0):
  等待 wakeup_is_paused() == true     ← 确保 WakeNet 已暂停
  while (s_mic_running):
    i2s_channel_read(s_mic_handle, buffer, 1024)  // 读取 32ms 音频
    websocket_send_binary(buffer, 1024)            // 发送给服务端
    vTaskDelay(40ms)                                // 节流匹配实时率

服务端 ASR 引擎:
  接收音频数据 → 火山引擎 ASR WebSocket → 返回识别文本

收到 LLM 实时回复（流式）:
  {"type":"session_status","status":"on_llm_cb"}
  └── 字幕显示在屏幕底部

收到 ASR 识别结果:
  {"type":"session_status","status":"on_iat_cb"}
  └── 字幕显示
```

### 阶段 9：ASR 结束 + LLM 推理

```
收到: {"type":"session_status","status":"iat_end"}
  ├── display_show_status("思考中...")  // 只改文字，不换表情
  └── audio_mic_stop()                  // 停止麦克风采集

此时:
  WakeNet: 仍暂停
  mic_task: 已停止
  I2S 麦克风: 空闲

服务端: LLM 推理 → TTS 合成 → 返回音频
```

### 阶段 10：LLM 回复 TTS 播放

```
（回到阶段 3-6，循环播放 TTS 音频）
```

### 阶段 11：会话结束

```
收到: {"type":"session_status","status":"session_end"} (JSON)
  if (s_session_ended):               // 二进制 "03" 已处理
    return  ← 跳过，drain check 会处理
  if (s_continue_dialogue):
    return  ← 连续对话中，不结束
  // 无二进制 "03" 的情况（纯文本提示音等）
  ├── s_audio_playing = false
  ├── 停止 drain_check_timer
  ├── display_show_status("等待唤醒...")
  ├── display_show_emotion("休息中")
  ├── audio_spk_stop()
  └── wakeup_resume()                  ← 恢复 WakeNet

收到纯文本: "session_end"
  if (s_session_ended || s_continue_dialogue):
    return  ← 跳过
  // 简单清理
  ├── s_audio_playing = false
  ├── display_show_status("等待唤醒...")
  ├── audio_spk_stop()
  └── wakeup_resume()                  ← 恢复 WakeNet

此时:
  WakeNet: 已恢复（重新读取 I2S）
  mic_task: 未启动
  状态: 回到阶段 1（待机等待唤醒）
```

### 阶段 12：连续对话（可选）

```
如果二进制 status="02"（TTS 结束但需继续对话）:
  ├── s_continue_dialogue = true
  ├── audio_spk_wait_drain()
  └── 启动 drain_check_timer

drain_check_timer_cb() (s_continue_dialogue 分支):
  if (audio_spk_check_drain_done()):
    ├── s_continue_dialogue = false
    ├── s_audio_playing = false
    ├── audio_spk_stop()
    ├── send_audio_over_internal()
    ├── wakeup_pause()                 ← 暂停 WakeNet
    ├── websocket_send_text({"type":"start"})  ← 自动开始下一轮
    ├── display_show_status("聆听中")
    ├── display_show_emotion("聆听中")
    └── audio_mic_start()              ← 启动麦克风采集
```

## 三、状态标志说明

| 标志 | 作用 | 设置时机 | 清除时机 |
|------|------|----------|----------|
| `s_audio_playing` | 音频正在播放 | `play_audio` / `tts_chunk_start` | `drain_check` 完成后 |
| `s_audio_over_sent` | 防止重复发送 `client_out_audio_over` | 发送后设为 true | 新 `play_audio` 到来时 |
| `s_session_ended` | 二进制 "03" 已收到 | 二进制 status="03" | drain check 处理后 |
| `s_continue_dialogue` | 连续对话标志 | 二进制 status="02" | drain check 处理后 |
| `s_wakenet_paused` | WakeNet 暂停标志 | 唤醒时 / iat_start 时 | session_end 时 |

## 五、GIF 动画卡顿问题（附带记录）

### 根因
LVGL 9 的 GIF 库默认使用 `ARGB8888` 格式（4 字节/像素），每帧渲染后需要转换为 RGB565 才能显示。120×120 的 GIF 每帧转换 57.6KB 数据，耗时显著。

### 已应用的优化
1. **移除 `lv_image_cache_drop`**：每帧 drop+re-cache 是最大性能瓶颈
2. **GIF 缩小到 120×120**：canvas 从 164KB 降到 72KB
3. **双缓冲**：DMA 传输和 LVGL 绘制并行
4. **Core 1 绑定**：LVGL 任务与音频/WiFi（Core 0）分离
5. **Canvas 分配在 PSRAM**：避免占用内部 RAM 导致 WiFi/唤醒任务失败

### 性能数据
- `get_frame`: 0-15ms（LZW 解码）
- `render`: 0-10ms（ARGB8888 像素填充）
- `invalidate`: 0-5ms（标记脏区域）
- `delay`: 80-100ms（GIF 帧间隔，10fps）
- `elaps`: 80-110ms（实际帧间隔，基本匹配）

### 未解决的尝试
- **RGB565 格式**：颜色错误（R/B 通道反转），已放弃
- **RGB565A8 格式**：LVGL 9 平面存储与 LVGL 8 交错存储不同，实现复杂，已放弃
